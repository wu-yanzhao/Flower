# 管理端无法打开：定位、修复与接口清单

> 目标页面：`http://localhost:5173/admin/index.html`
> 结论：**页面本身没有坏**。HTML、入口脚本、静态路径、后端接口全部正常。
> 真正原因是「鉴权失效/后端不可达时，前端静默吞掉异常」，导致页面永远停在"加载中…"，看起来像打不开。

---

## 一、根本原因与判断依据

排查顺序是先证伪、再定位，避免凭感觉改代码：

| # | 怀疑点 | 验证方式 | 结论 |
| --- | --- | --- | --- |
| 1 | 端口占用 | netstat 查 3000/5173 | 服务都在监听，排除 |
| 2 | 跨域 | `/api/health` 经 5173 转发 → 200 | 同源 + 转发，排除 |
| 3 | 静态资源路径 | 取 index.html 全部 src/href 逐个请求 | 9 个资源全部 200，排除 |
| 4 | DOM 与脚本不对齐 | 提取页面 id 与脚本 `getElementById` 交叉比对 | 全部命中，排除 |
| 5 | 组件缺失 | 检查 Chart/UI 各成员导出 | 全部存在，排除 |
| 6 | 后端接口返回异常 | 用管理员 token 实打一遍 7 个接口 | 全部 200，字段名与前端完全一致，排除 |
| **7** | **浏览器运行时行为** | **jsdom 真实执行页面脚本，模拟 3 种场景** | **命中** |

### 关键证据（jsdom 真实渲染结果）

| 场景 | 修复前表现 | 修复后表现 |
| --- | --- | --- |
| A. 正常管理员 token | 销售额 15667、趋势图 3307 字符、订单/日志正常渲染 | 完全一致（未改变正常路径） |
| B. token 失效（过期） | 所有卡片**永远停在"加载中…"，不报错、不跳登录** | 显示"数据加载失败：访问令牌签名校验失败"并自动回登录页 |
| C. 后端不可达 | 同样永远"加载中…"，控制台仅一条 unhandled rejection | 显示"数据加载失败：无法连接后端服务，请确认后端已启动（http://localhost:5173/api）" |

### 三处缺陷的代码位置

1. **`web/assets/js/api.js` `request()` 没有 `.catch()`**
   `fetch` 在后端未启动时会 reject，异常无人接管 → Promise 永远不 settle → 面板不更新。
2. **`request()` 没有超时控制**
   后端"假死"（接受连接但从不响应）时请求永久挂起。
3. **401 只 `toast + clear`，不跳转**
   凭证失效后页面仍在渲染内容，用户看到的是半残 iframe 式界面。
4. **`web/admin/js/dashboard.js` 6 个 `.catch(function () {})` 是空实现**
   即使错误传到 here 也被吞掉，界面保留初始的"加载中…"。

## 二、修改文件清单与关键改动

| 文件 | 改动 | 原因 |
| --- | --- | --- |
| `web/assets/js/api.js` | 新增 `fetch().catch()`，把网络异常包装为 `code='NETWORK_ERROR'` 的 `Error` | 让调用方能拿到可读错误而不是 unhandled rejection |
| `web/assets/js/api.js` | 引入 `AbortController` + 15 秒超时（`API_TIMEOUT` 可覆盖） | 防后端假死导致永久 pending，超时后抛 `code='TIMEOUT'` |
| `web/assets/js/api.js` | 抽 `handleUnauthorized()`：清凭证 → 提示 → 跳登录页带 `redirect` 来源 | 凭证失效时给出明确去向，而不是停在半加载界面 |
| `web/assets/js/api.js` | **边界：仅当本次请求确实携带 token 才跳登录** | 防止游客浏览首页时被匿名接口的 401 无脑弹到登录页 |
| `web/assets/js/ui.js` | 新增 `UI.panelError(target, err, retry)` | 各面板错误态统一渲染，可选重试按钮 |
| `web/admin/js/dashboard.js` | 6 处空 `catch` 改为 `fail(id)` 渲染可见错误 | 错误不再被静默吞掉 |
| `web/admin/js/dashboard.js` | 新增 `emptyOr(id, render)`：空数组渲染"暂无数据" | 避免图表组件对空数据算出 NaN，这是新数据库常见的边界 |
| `web/admin/js/dashboard.js` | 修复被误删的 `loadOverview()` 函数头 | 编辑过程中的语法事故，已 `node --check` 通过 |

> 未改动：`web/admin/index.html`（结构本身正确）、后端任何文件。

## 三、管理端数据概览页依赖的接口清单

**公共约定**：路径前缀 `/api/admin`；全部 `GET`；全部需要 `Authorization: Bearer <token>` 且角色为 `admin`（由 `adminOnly` 中间件统一拦截）。
**响应封装**：`{ code: 0, message: "ok", data: ... }`，出错时 `code` 非 0。

### 3.1 GET /api/admin/stats/overview — 核心指标

- 请求参数：无
- 响应字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| sales | number | 累计销售额 |
| todaySales | number | 今日销售额 |
| orderCount | number | 订单总数 |
| todayOrders | number | 今日订单数 |
| avgOrder | number | 客单价 |
| userCount | number | 注册用户数 |
| flowerCount | number | 在售商品数 |
| pendingCount | number | 待发货数 |
| shippedCount | number | 待收货数 |
| reviewCount | number | 评价数 |
| lowStock | number | 库存 ≤10 的商品数 |

### 3.2 GET /api/admin/stats/trend — 销售趋势

- 参数：`days`（可选，默认 7，限制 1~30）
- 响应 `Array<{ date: string, amount: number, sales: number, orders: number }>`

### 3.3 GET /api/admin/stats/category — 分类销量占比

- 参数：无
- 响应 `Array<{ id: number, name: string, quantity: number }>`

### 3.4 GET /api/admin/stats/top — 热销商品榜

- 参数：`limit`（可选，默认 5，限制 1~20）
- 响应 `Array<{ id, name, image, sales, stock, sold, amount, quantity }>`

### 3.5 GET /api/admin/stats/status — 订单状态分布

- 参数：无
- 响应 `Array<{ status: string, name: string, count: number }>`
- `status` 取值：`pending | paid | shipped | completed | canceled`

### 3.6 GET /api/admin/stats/recent — 最新订单

- 参数：`limit`（可选，默认 8，限制 1~20；页面传 6）
- 响应 `Array<{ id, order_no, pay_amount, status, created_at, nickname }>`

### 3.7 GET /api/admin/logs — 操作日志

- 参数：`limit`（可选，默认 10，上限 50；页面传 6）
- 响应 `Array<{ id, admin_id, admin_name, module, action, detail, created_at }>`

### 3.8 错误码

| code | 触发条件 | 前端行为 |
| --- | --- | --- |
| 0 | 成功 | 渲染数据 |
| 401 | 无 token / token 校验失败 / 用户已删除 | 带 token 的请求→清凭证并跳登录页；匿名请求→仅抛错，由调用方决定 |
| 403 | 账号被禁用，或角色非管理员 | 抛错；管理端守卫另行跳回首页并提示"仅管理员可访问后台管理系统" |
| 其它 | 业务校验失败 | `UI.panelError` 在对应面板显示后端 message |
| NETWORK_ERROR | 后端未启动/不可达 | 面板显示"无法连接后端服务，请确认后端已启动（<地址>）" |
| TIMEOUT | 15 秒无响应 | 面板显示"请求超时，请检查后端服务是否正常响应" |

> 字段一致性已用实打的接口数据核对：`overview` 的 11 个字段、`trend` 的 `date/sales`、`category`、`top` 的 `name/quantity`、`status` 的 `status/count`、`recent` 的 `order_no/pay_amount/nickname/created_at`、`logs` 的 `module/admin_name/action/created_at`，与 `dashboard.js` 引用完全对应。

## 五、异常与边界处理说明

1. **并发 401 去重**：7 个面板同时请求时，`authRedirecting` 标志保证只跳转一次，避免竞态重复导航。
2. **登录页自我保护**：`handleUnauthorized` 检测到当前是 `login.html`/`register.html` 时不跳转，防止无限重定向。
3. **匿名请求不被误伤**：只有请求真实携带 token 时才清理凭证并跳转；游客浏览首页不受影响。
4. **超时可配置**：默认 15 秒，可通过 `window.API_TIMEOUT = 30000` 调整，`AbortController` 不可用的老浏览器自动降级为无超时。
5. **空数据降级**：所有图表面板在 `list` 为空时渲染"暂无数据"，不进入绘图逻辑。
6. **错误可见**：任何面板失败都显示后端原始 message，便于答辩现场快速定位。
7. **可恢复**：`UI.panelError(target, err, retry)` 支持传重试回调，后续页面需要重试点时直接复用。
