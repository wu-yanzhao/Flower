# 15 · 答辩口述稿：文件结构与数据库存储

> 用于回应老师两个提问，可直接口述。约 3 分钟，学生口吻，不含代码。
> 提问一：为什么项目中有这么多 HTML、JS 结构，应该怎么处理？
> 提问二：数据库如何存储数据？

---

## 回答一：为什么有这么多 HTML、JS，怎么处理

老师好，我先回答第一个问题。

文件多，是因为我们做的是前后端分离的网上花店，分顾客端和管理端两个门户，功能包括浏览商品、购物车、下单支付、订单管理和后台管理，页面和交互自然就多。

这些文件各有职责：**HTML 负责页面结构**，也就是页面骨架上有哪些按钮、表单和商品卡片；**JS 负责交互逻辑**，比如点击筛选、加入购物车、向后端发请求、把数据显示到页面上；CSS 负责样式。我们做到**一个页面对应一个 HTML，并配一个同名 JS**，比如 flowers.html 对应 flowers.js，看文件名就知道它管哪个页面。

至于怎么保持清晰、便于维护，我主要做了三点：
第一，**按功能和页面分类**——顾客端页面放在 web 目录，管理端页面统一放进 admin 子目录，源码不混在一起；
第二，**合理命名**——文件名和页面功能一致，不看代码也能猜到用途；
第三，**分层组织**——把公共的请求发送统一封装在 api.js，公共组件和样式单独抽出来复用；后端也按路由、控制层、数据层分目录。

所以文件虽然多，但每个文件各司其职、边界清楚，找起来快，改一个不会牵连其他，以后加新页面或新功能也很方便。

## 回答二：数据库如何存储数据

老师好，回答第二个问题。

我们用的是 SQLite 数据库，整个库就是一个文件 flower.db，部署和拷贝都很方便。

存储方式上，我用**一张张表来保存不同类别的数据**：用户表存账号信息，商品表存鲜花，还有分类表、购物车表、订单表、订单明细表、评价表、收藏表、收货地址表和操作日志表，一共十张表。

每张表里的**字段用来描述属性**，比如商品表里有名称、价格、库存、销量、图片这些字段；表里的**每一行是一条具体记录**，比如某一束玫瑰就是一个商品记录。

表与表之间通过**关联关系**连接相关信息：比如订单表里用 user_id 关联是哪个用户下的单，订单明细表用 order_id 关联所属订单，这样订单和商品信息就串起来了，既避免重复存储，也保证数据一致。

## 补充：本项目的特别之处

最后我补充三点。一是**结构清晰**，前后端分离、按层按功能分目录，职责分明；二是**功能完整**，从浏览、下单、支付到评价，再到后台管理，形成了完整闭环；三是**数据与页面配合自然**，页面上看到的内容就是数据库里查出来的数据，通过统一接口衔接。

同时因为分层清楚、表结构也预留了扩展空间，后续要加新功能或新字段都比较方便。以上是我的回答，谢谢老师。
