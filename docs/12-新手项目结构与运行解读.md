# 12 · 新手项目结构与运行解读（零基础版）

> 面向第一次接触本项目的人：先讲整体用途和一次请求的流转，再逐个文件说明作用，最后把「路由 / 控制层 / scripts / 冒烟测试 / 接口」这些词钉到具体文件上。
> 全程结合真实路径，不堆术语，不贴大段代码。

## 一、整体概览

### 1.1 这是个什么程序

「鲜花订购与管理系统」——一个网上花店，毕业设计项目。分两个门户：

- **顾客端**：逛花、搜索筛选、看详情、加购物车、下单、支付、看订单、评价
- **管理端**：数据看板、管商品/分类/订单/用户/评价

技术上前后端分离：

| 部分 | 代码位置 | 入口 | 职责 |
| --- | --- | --- | --- |
| 前端（顾客端） | `web/*.html` + `web/assets/js/*.js` | `web/index.html` | 界面展示、收集点击、调后端接口 |
| 前端（管理端） | `web/admin/*.html` + `web/admin/js/*.js` | `web/admin/index.html` | 后台管理界面 |
| 前端独立服务 | `web/server.js` | 自身 | 发页面 + 把 `/api` 请求转发给后端（端口 5173） |
| 后端服务 | `server/src/**` | `server/src/app.js` | 收请求、跑业务、读写数据库（端口 3000） |
| 数据库 | `server/data/flower.db` | — | 一个 SQLite 文件，存全部数据 |

### 1.2 一次请求怎么流转（以「搜索鲜花」为例）

1. 顾客在 `web/flowers.html` 输入关键词、点搜索
2. 页面脚本 `web/assets/js/flowers.js` 调用 `API.get('/flowers', 条件)`
3. `web/assets/js/api.js` 用 `fetch` 发请求到 `/api/flowers?keyword=玫瑰&sort=sales`，自动带上登录 token
4. 请求到达后端 `server/src/app.js:69`（`app.use('/api', routes)`）
5. `server/src/routes/index.js:30` → `server/src/routes/catalog.routes.js:23` 匹配到这条路由
6. 路由把请求交给 `server/src/controllers/flower.controller.js:21` 的 `list()` 函数
7. `list()` 拼 SQL 条件、调 `server/src/db/` 从 `flower.db` 查出数据
8. 数据按统一格式 `{code:0, message, data}` 原路返回
9. `api.js` 解包 `json.data`，`flowers.js` 生成商品卡片显示出来

下单流程更长（在 `@order.controller.js` 里用事务保证「减库存 + 生成订单 + 清购物车」要么全成要么全撤），但骨架完全一样。

## 三、核心概念解释（对应到真实文件）

### 3.1 接口 = "后厨对外开的窗口"

**通俗说法**：接口就是后端提供的一个个「固定网址 + 固定规矩」的服务窗口。你按规矩送请求，它按规矩回数据。

**在本项目里具体指**：

- 基础地址：`http://localhost:3000/api`（`docs/03-接口文档.md:3`）
- 一条条接口的定义处：`server/src/routes/*.routes.js` 里的 `router.get/post/...`
- 完整清单：`docs/03-接口文档.md`
- 前端调用处：`web/assets/js/api.js`

**举例**：`GET /api/flowers?keyword=玫瑰&sort=sales` 就是「商品列表接口」：
- 定义在 `catalog.routes.js:23`
- 实现在 `flower.controller.js:21`
- 返回 `{code:0, message, data:{list, total, ...}}`

**统一约定**：响应永远是 `{code, message, data}`，`code=0` 才成功。这是前后端共同的"普通话"。

### 3.2 路由 vs 接口（最容易混）

| | 接口 | 路由 |
| --- | --- | --- |
| 是什么 | 对外承诺的服务（顾客视角：我能点什么） | 后端内部的分发代码（后厨视角：这单转给谁） |
| 在哪定义 | `docs/03-接口文档.md`（文档约定） | `server/src/routes/*.routes.js`（代码） |
| 视角 | 给调用方看，讲「路径+参数+返回」 | 给程序看，讲「网址匹配到哪个函数」 |

**关系**：一个接口 ≈ 一条路由规则 + 一个控制层函数 + 返回结果。路由只是接口实现的一部分。

本项目路由还兼「门禁」职责：
- `order.routes.js:10` 的 `router.use(authRequired)` → 整个订单模块必须登录
- `catalog.routes.js:15` 的 `adminOnly` → 只有管理员能改分类

### 3.3 控制层 vs 业务逻辑

**控制层（controller）** = 放业务函数的那一层文件夹，即 `server/src/controllers/` 下 11 个 `.controller.js`。
**业务逻辑** = 这些函数里面写的具体规则。

通俗说：控制层是「厨师这个岗位」，业务逻辑是「这道菜具体怎么做」。

举例：`flower.controller.js:21-63` 的 `list()` 就是一段业务逻辑：
解析分页/关键词/分类/价格/排序 → 拼 `WHERE` 条件（排序用白名单防 SQL 注入）→ 调 `db.all()` 查询 → 返回分页结果。

> 注意：本项目业务逻辑就写在 controller 里，**没有单独的 service 层**。答辩别说自己做了三层架构里的 service 分层，实事求是说「路由 + 控制层 + 数据层」即可。

### 3.4 scripts 是什么（有两处，别混）

| 位置 | 内容 | 性质 |
| --- | --- | --- |
| `server/scripts/` | `seed.js`（空库时写入演示数据）、`reset.js`（清空重建）、`smoke-test.js`（接口冒烟）、`admin-test.js`（后台接口测试）、`upload-test.js`（上传测试） | 后端开发工具箱 |
| 根目录 `scripts/` | `gen_images.py`、`gen_ui.py` | 离线生成图片/UI 素材，跟网站运行完全无关 |
| `package.json` 的 `scripts` 字段 | 不是文件夹，是「命令别名表」 | 让 `npm run test:api` 映射到 `node scripts/smoke-test.js` |

**脚本 vs 正式业务代码**：

- 正式业务代码在 `server/src/**` 和 `web/**`，网站运行时一直在跑，用户直接/间接用到
- 脚本是要人手动敲命令才跑一次的工具，跑完就结束，顾客永远碰不到
- 判断方法：看它是不是被 `app.js` 引入——`scripts/` 里的文件没有一个被 `app.js` require

### 3.5 冒烟测试 vs 普通测试

| | 冒烟测试 | 普通（单元）测试 |
| --- | --- | --- |
| 文件 | `server/scripts/smoke-test.js` | `server/test/jwt.test.js`、`password.test.js` |
| 测什么 | 真实 HTTP 请求走完整流程：注册→登录→浏览→搜索→加购→下单→支付→发货→收货→评价→统计 | 直接测单个函数：token 签名/验签、密码加密校验 |
| 要先启动后端吗 | 要（先 `npm start`，再 `npm run test:api`） | 不要 |
| 命令 | `npm run test:api`（也可双击 `接口测试.bat`） | `npm run test:unit` |
| 目的 | 验证「系统整体还跑得通吗」，像开机先看有没有冒烟 | 验证「某个零件的逻辑对不对」 |

另外 `admin-test.js`、`upload-test.js` 也是接口级脚本测试，分别专测后台和上传。
「冒烟」这个词来自硬件行业：通电后先看有没有冒烟，没问题再细测。这里指先快速验证主流程通不通。

## 四、调用关系链

### 4.1 主链（所有请求都走这条路）

```
浏览器页面(web/*.html)
  → 页面脚本(web/assets/js/*.js)
  → api.js 封装 fetch，加 token，请求 /api/xxx
  → [前端单独启动时] web/server.js 转发到后端 3000
  → server/src/app.js:69  app.use('/api', routes)
  → server/src/routes/index.js  分发到具体 .routes.js
  → 中间件 middleware/auth.js  验 token / 管理员权限（如需）
  → server/src/controllers/xxx.controller.js  业务逻辑
  → server/src/db/  拼装执行 SQL → data/flower.db
  → 原路返回 {code, message, data}
  → api.js 检查 code、解包 data
  → 页面脚本渲染到 html
```

### 4.2 场景一：搜索鲜花（游客可用）

`flowers.html` → `flowers.js` → `api.js` `GET /flowers` → `app.js` → `routes/index.js` → `catalog.routes.js:23`（无门禁）→ `flower.controller.js:21 list()` → `db` → `flower.db` → 返回商品数组 → 渲染卡片。

### 4.3 场景二：提交订单（必须登录 + 事务）

`checkout.html` → `checkout.js` → `api.js` `POST /orders` → `app.js` → `routes/index.js` → `order.routes.js:15`（`:10` 的 `authRequired` 先生效）→ `order.controller.js` 的 `create()` → 开启事务：检查库存 → 生成订单与明细 → 扣库存 → 清购物车 → 提交（任一步失败全部回滚）→ 返回订单信息 → 跳支付页。

### 4.4 场景三：验证系统是否被改坏

敲 `npm run test:api` → 跑 `scripts/smoke-test.js` → 它像真人一样调上面所有接口 → 打印每项 ✓/✗ → 看失败项定位问题。

## 五、新手阅读顺序与注意事项

### 5.1 推荐顺序（一条线打通，不要横向铺开）

1. `README.md` + `docs/05-答辩指南.md` —— 先知道系统能干嘛
2. `docs/03-接口文档.md` —— 看前后端「约定」了哪些接口
3. `web/flowers.html` —— 看一个页面长什么样
4. `web/assets/js/api.js` —— 理解前端怎么发请求（**最关键的一个文件**）
5. `server/src/app.js` —— 看后端骨架
6. `server/src/routes/index.js` → `catalog.routes.js` —— 看请求怎么被分发
7. `server/src/controllers/flower.controller.js` —— 看业务逻辑怎么写
8. `server/src/db/schema.sql` → `db/index.js` —— 看数据怎么存
9. `server/scripts/smoke-test.js` —— 跑一遍，看完整流程串起来
10. 进阶再读 `middleware/auth.js`、`db/index.js` 的事务、`order.controller.js` 的下单逻辑

### 5.2 注意事项（答辩前必看）

- **别一上来读 11 个 controller**，先把「商品列表」这一条线从页面跟到数据库，其余都是同一个套路。
- **这些不是你写的代码**：`.idea/`、`node_modules/`、`data/flower.db`、`logs/server.log`。答辩被问到要说清是工具/依赖/数据/日志。
- **两种启动方式别混端口**：后端 3000，前端 5173。前端服务只是转发 `/api`，真正干活的是后端。
- **JWT_SECRET 默认每次启动随机生成**（`config.js:43-52`）：重启后端后旧 token 失效、需要重新登录。答辩演示登录前先确认这一点，或提前在 `.env` 配固定密钥。
- **改前端不用重启后端**（静态文件实时读取）；**改后端必须重启**服务。
- **接口统一返回 `{code, message, data}`**，`code=0` 才算成功；看到 401 就是没登录或登录过期。
- **演示数据可被重置**：`npm run reset` 会清空重建，答辩前若数据乱了可用它恢复，或双击 `重置演示数据.bat`。

## 六、一句话记忆

> `web/` 是店面，`server/src/app.js` 是后厨总管，`routes/` 是传菜员（路由），`controllers/` 是厨师（控制层+业务逻辑），`data/flower.db` 是仓库，`scripts/` 是开店工具箱，`docs/03-接口文档.md` 是菜单。顾客点单 → 传菜员分派 → 厨师做菜 → 仓库取货 → 原路端回。
