# 05 · 答辩指南（演示脚本与常见问题）

## 5.1 五分钟演示脚本（建议按此顺序）

**第 1 步 · 启动与总览（30 秒）**
> "系统采用前后端分离架构，前端是原生 HTML/CSS/JS，后端是 Node.js + Express，数据库使用 SQLite 单文件，
> 除了 express 之外没有任何第三方依赖，断网也能完整演示。"

双击 `启动项目.bat`，浏览器自动打开首页：展示主视觉、分类入口、店长推荐、热销榜、购物流程。

**第 2 步 · 顾客端购物全流程（2 分钟）**

1. 点右上角「登录」→ 点击"填入顾客账号"按钮 → 用 `customer / 123456` 登录
2. 首页点「立即选购鲜花」→ 演示分类筛选（爱情玫瑰）、价格区间、排序切换、关键词搜索
3. 进入某商品详情 → 展示花语、花材、包装、评分、库存、收藏按钮
4. 点击「加入购物车」→ 购物车页勾选、改数量 → 演示满减（满 300 减 20 / 满 500 减 50）
5. 「去结算」→ 选择/新增收货地址 → 提交订单 → 模拟支付页选择支付方式 → 确认支付
6. 我的订单 → 展示状态 Tab 与订单详情中的**物流时间轴**（订单跟踪）

**第 3 步 · 确认收货与评价（40 秒）**
> 订单状态为「待收货」时点击确认收货 → 状态变为已完成 → 「评价晒单」打 5 星并写评价
> → 回到商品详情的"用户评价"页签可看到刚提交的评价。

**第 4 步 · 管理端数据概览（1 分钟）**
> 退出登录，用 `admin / admin123` 登录（会自动进入后台）。

- 4 个核心指标卡片：销售总额、订单总数、待发货/待收货、注册用户
- 近 7 日销售趋势折线图（可切换 14/30 天）
- 各分类销量占比环形图、热销商品 TOP5 柱状图、订单状态分布
- 最新订单与操作日志

**第 5 步 · 管理端业务操作（1 分钟）**

- 商品管理：新增一件商品（用内置图片选择器）→ 上架/下架 → 库存 +10 → 尝试删除已有订单的商品（会被拒绝）
- 订单管理：按状态筛选 → 打开订单详情 → 对待发货订单执行"发货"→ 状态推进
- 用户管理：禁用某账号（该账号将无法登录）、重置密码为 123456
- 评价管理：隐藏/展示评价、商家回复

**第 6 步 · 收尾总结（30 秒）**
> "系统实现了从选购到售后的完整闭环，并具备权限控制、数据校验、事务一致性、状态机约束和操作日志，
> 保证了业务的正确性与安全性。"

## 5.2 项目亮点（答辩时主动强调）

1. **业务闭环完整**：浏览 → 搜索 → 详情 → 收藏 → 购物车 → 下单 → 支付 → 发货 → 收货 → 评价，全流程贯通
2. **数据一致性**：下单扣库存与取消回滚均在数据库事务中完成，杜绝超卖
3. **订单状态机**：状态流转白名单校验，杜绝"已完成后再支付"等非法操作
4. **权限与安全**：JWT 鉴权 + 角色中间件 + scrypt 加盐哈希 + 参数化查询防注入
5. **零外部依赖**：图表自研 SVG、图片本地 SVG、数据库内置模块，断网可演示
6. **工程规范**：路由—控制器—工具三层分层、统一响应格式、统一错误处理、操作日志审计
7. **可测试性**：内置 35 项接口自动化测试脚本，一条命令即可验证系统健康度

## 5.3 常见问题与回答

**Q1：为什么不用 Vue/React 等主流框架？**
A：本项目定位是"可稳定运行、便于演示与评审"的课程设计。原生实现免构建、免打包，
避开了 npm 安装失败、构建产物丢失等风险；同时代码结构清晰，便于展示对 DOM、HTTP、异步的理解。
架构上前端通过 `api.js` 统一封装请求，若后续接入框架，只需替换视图层，接口层可完全复用。

**Q2：为什么选择 SQLite 而不是 MySQL？**
A：SQLite 是单文件数据库，无需安装配置，便于随项目一起提交且随时可复现；
其 SQL 语法与 MySQL 高度一致，后续迁移只需更换连接层。数据库连接封装在 `db/driver.js`，
已预留 `better-sqlite3` 兜底，更换数据库不影响业务代码。

**Q3：如何防止超卖？**
A：下单时在同一事务内校验库存 → 扣减库存 → 写入订单与明细；
任一步失败则整体回滚。取消订单时同样在事务中回滚库存与销量。

**Q4：密码是如何存储的？**
A：使用 Node 内置 `crypto.scryptSync` 生成加盐摘要，盐值随机生成并单独存储，
数据库中不存在明文密码，也无法通过彩虹表反查。

**Q5：支付是真的吗？**
A：是模拟支付。系统预留了支付方式字段与支付时间，点击确认支付后订单状态流转为"待发货"。
若接入真实支付，只需在 `pay` 接口中调用第三方 SDK 并回调更新订单状态，业务逻辑无需改动。

**Q6：系统的并发能力如何？**
A：SQLite 适合单机与中小型场景。若需支持高并发，可将连接层替换为 MySQL/PostgreSQL，
并引入连接池与乐观锁（版本号）控制库存，现有事务逻辑可平滑迁移。

**Q7：有哪些可以扩展的方向？**
A：① 接入真实支付与物流查询接口；② 增加优惠券/秒杀/拼团营销模块；
③ 增加推荐算法（基于浏览与购买记录）；④ 增加小程序或移动端适配；⑤ 引入 Redis 缓存热点数据。
