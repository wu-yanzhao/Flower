## 三、启动失败根因与修复（共 3 处）

### 1. `启动前端.bat` 编码错误（本次启动失败的直接原因）

- **现象**：双击后满屏乱码、报"找不到模块 `E:\Flower\server.js`"。
- **根因**：该 bat 曾以 **UTF-8** 保存，而 cmd 按 GBK 解析批处理。中文字节错位导致 `cd` 行解析失败，脚本停留在 `E:\Flower` 根目录执行 `node server.js`，而 `server.js` 在 `web/` 下。
- **修复**：重写并转存为 **GBK + CRLF**（与旧 bat 一致），去掉 `chcp 65001`。
- **注意**：以后不要用编辑器把 `.bat` 另存为 UTF-8。

### 2. PowerShell 终端用了 CMD 语法

- **现象**：`set PORT=8000 && node server.js` 在 VS Code 终端报错。
- **根因**：VS Code 默认终端是 PowerShell，`set` 与 `&&` 是 CMD 语法。
- **修复**：`server.js` 的端口占用提示、`docs/08`、README 均已补上两种写法：
  - CMD：`set PORT=8080 && node server.js`
  - PowerShell：`$env:PORT="8080"; node server.js`

### 3. 端口被残留进程占用

- **现象**：`[错误] 端口 5173 已被占用`。
- **根因**：此前调试留下的后台服务未关闭。
- **修复**：已全部结束，3000/5173 均已释放。**启动前若再遇占用，先关旧窗口或按上面语法换端口。**
