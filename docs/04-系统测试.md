执行方式：

```bash
cd E:\Flower\server
npm start          # 终端 1：启动服务
npm test           # 终端 2：顾客端 -> 重置 -> 管理端 -> 重置 -> 扩展接口 -> 单元测试
# 或分别执行：npm run test:api / test:admin / test:extended / test:upload / test:unit
```

**执行结果：`npm test` 共 359 项断言，通过 359 项，失败 0 项（35 + 49 + 223 + 52）；
另有上传接口 13 项与页面功能用例 30 项，合计 402 项全部通过。**
测试会自建账号、商品与订单，如需还原演示数据，执行 `npm run reset`。

## 4.4 安全性与边界测试

| 用例 | 场景 | 结果 |

| S-07 | 关键词含特殊字符 | 走参数化查询，无 SQL 注入 |

## 4.5 测试执行健壮性

`npm run reset` 具备两种执行模式，避免服务占用文件导致重置失败：

| 场景 | 行为 |
| --- | --- |
| 服务未运行 | 删除 `data/flower.db` 后重建并写入演示数据 |
| 服务运行中（Windows 报 EBUSY） | 自动降级为「清空全部数据表」方式重建，数据立即生效，无需重启服务 |

边界值、异常输入、错误处理、状态机与关键回归场景均有专门用例覆盖，满足毕业设计演示与验收要求。
