## 一、高严重度（致命 / 严重）

### B1【致命】`GET /api/reviews/mine` 必崩 500
- **位置**：`server/src/routes/member.routes.js:26`
- **根因**：路由引用 `reviewController.mine`，但控制器导出的是 `exports.myList`（`review.controller.js:56`），调用一个不存在的方法 → `TypeError`。
- **修复**：
  ```js
  // 改前
  router.get('/reviews/mine', authRequired, asyncHandler(reviewController.mine));
  // 改后
  router.get('/reviews/mine', authRequired, asyncHandler(reviewController.myList));
  ```
- **验证**：`GET /api/reviews/mine` 由 500 → **200，code=0**。

### B2+B3【严重】管理员取消订单只回滚库存、漏回退销量
- **位置**：`server/src/controllers/order.controller.js:320-330`（`adminSetStatus` 的取消分支）
- **根因**：用户端取消（`cancel`，213-222 行）会“回滚库存 + 回退销量 + 销量钳制非负”，但管理员取消只回滚了 `stock`，导致 `flowers.sales` 虚高，污染销量排行 / 热销 TOP / 分类饼图。
- **修复**：与用户端保持一致：
  ```js
  items.forEach((it) => {
    db.run('UPDATE flowers SET stock = stock + ?, sales = sales - ?, updated_at = ? WHERE id = ?',
      [it.quantity, it.quantity, now(), it.flower_id]);
    db.run('UPDATE flowers SET sales = CASE WHEN sales < 0 THEN 0 ELSE sales END WHERE id = ?', [it.flower_id]);
  });
  ```
- **验证**：实测下单 2 件 → `sales+2`；管理员取消 → `sales` 回到原值、`stock` 同步回滚。

### B4【严重】登录接口可枚举用户名
- **位置**：`server/src/controllers/auth.controller.js:50-53`
- **根因**：先判断“账号不存在”再验密码，两种文案不同，攻击者可借此确认哪些用户名已注册。
- **修复**：存在 / 不存在 / 密码错误统一为同一文案；仅对已登录者（知道自己的账号）提示“已禁用”。
  ```js
  const user = db.get('SELECT * FROM users WHERE username = ?', [data.username]);
  if (!user) throw new HttpError(401, '账号或密码错误');
  if (!verifyPassword(data.password, user.password_hash)) throw new HttpError(401, '账号或密码错误');
  if (user.status !== 'active') throw new HttpError(403, '账号已被禁用，请联系管理员');
  ```
- **验证**：用不存在账号与错误密码登录，返回文案完全一致（均“账号或密码错误”）。

### B5【严重】JWT 密钥硬编码默认值
- **位置**：`server/src/config.js:35-36`
- **根因**：默认密钥写在代码里，仓库公开即可伪造 admin token。
- **修复**：未配置 `JWT_SECRET` 时每次启动随机生成并显式告警；要求正式部署在 `.env` 配置固定强随机值（`.env.example` 同步更新）。
  ```js
  jwtSecret: process.env.JWT_SECRET || (() => {
    const random = crypto.randomBytes(32).toString('hex');
    console.warn('[安全提示] 未配置 JWT_SECRET，已使用本次启动随机生成的密钥；重启后旧 token 将失效……');
    return random;
  })(),
  ```
  > 注意：随机密钥意味着**重启后端后旧 token 失效、需重新登录**（符合无状态会话预期）。

## 二、中严重度

### B5a【中】JWT 签名比较非恒定时间 & 未校验算法
- **位置**：`server/src/utils/jwt.js`（`verify`）
- **根因**：`expected !== s` 是普通字符串比较（计时侧信道）；且未校验 header `alg`，存在 `alg=none` 降级风险。
- **修复**：校验 `alg === 'HS256'`；签名改用 `crypto.timingSafeEqual` 做恒定时间比较。

### B6【中】`logout` 是空操作，token 永不失效
- **位置**：`server/src/controllers/auth.controller.js`（logout）、`server/src/middleware/auth.js`
- **根因**：登出只向前端返回成功，服务端未做任何失效处理，token 在 7 天有效期内存续可用。
- **修复**：为 token 增加 `jti` 声明；登出时把 `jti` 加入进程内黑名单；`resolveUser` 校验命中即 401。
  ```js
  // auth.js
  const revokedJtis = new Set();
  function revokeToken(token) { /* jwt.verify 取出 jti 后加入集合 */ }
  // resolveUser 内：if (payload.jti && revokedJtis.has(payload.jti)) throw 401
  // auth.controller.logout：revokeToken(req.token || extractToken(req));
  ```
  > 黑名单为内存级，重启后清空；已过期 token 仍按 `exp` 自然失效——对毕业设计演示足够，且逻辑严密。

### B7【中】隐藏/删除评价后商品评分不同步
- **位置**：`server/src/controllers/review.controller.js`（setStatus / remove）
- **根因**：仅 `create` 重算了 `flowers.rating`，隐藏、删除评价时不重算，导致评分冗余字段失真（审计发现 18 个商品中 6 个不一致）。
- **修复**：新增 `recomputeRating(db, flowerId)` 并在 `setStatus`、`remove` 调用；删除前先取出 `flower_id` 以正确重算。
- **验证**：隐藏可见评价 → 评分重算；恢复可见 → 评分回到原值。

### B8【中】订单号无去重，高并发可碰撞
- **位置**：`server/src/utils/helpers.js`（`generateOrderNo`）
- **根因**：`FS + 秒级时间戳 + 4 位随机`，同秒内多次下单有碰撞概率（实测同秒 200 次约碰撞 1 次），命中 `orders.order_no UNIQUE` 会下单失败。
- **修复**：支持传入 `db`，生成后查库做唯一性校验并有限重试；无 `db` 时退回原高熵生成。
  ```js
  function generateOrderNo(db) {
    const build = () => `FS${stamp}${String(crypto.randomInt(0,10000)).padStart(4,'0')}`;
    if (!db) return build();
    for (let i=0;i<10;i++){ const no=build(); if(!db.get('SELECT 1 FROM orders WHERE order_no=?',[no])) return no; }
    return `${build()}${crypto.randomInt(100,1000)}`;
  }
  ```
  `order.controller.js` 调用处改为 `generateOrderNo(db)`。

### B13【低→中】同一订单只能评价一次（无法按商品分别评价）
- **位置**：`server/src/controllers/review.controller.js`（`create`）
- **根因**：存在性检查用 `WHERE order_id = ?`（整单），但表结构 `UNIQUE(order_id, flower_id)` 本意是按“订单+商品”唯一；前端 `orders.js` 也按商品逐条提交 `items`。
- **修复**：移除整单检查，循环内按 `(order_id, flower_id)` 判重，支持多商品分别评价。
  ```js
  const dup = db.get('SELECT 1 FROM reviews WHERE order_id = ? AND flower_id = ?', [order.id, flowerId]);
  if (dup) throw new HttpError(400, `「${matched.flower_name}」已评价，请勿重复提交`);
  ```

## 三、低严重度

### B9【低】`.env.example` 缺少 `STATIC_DIR`
- **位置**：`server/.env.example`
- **修复**：补充 `STATIC_DIR` 注释项（代码 `config.js` 早已支持）。

### B10【低】`upload-test.js` 上传目录指向废弃路径
- **位置**：`server/scripts/upload-test.js:17`
- **根因**：`UPLOAD_DIR` 指向 `web/assets/images/uploads`，但上传控制器实际写入 `server/static/uploads`，导致测试清理/断言错位。
- **修复**：`UPLOAD_DIR = path.resolve(__dirname, '..', 'static', 'uploads')`。

### B11【低】`makeTransaction` 注释与实际不符
- **位置**：`server/src/db/driver.js`
- **根因**：注释声称“用计数器做嵌套事务保护”，但实现只是裸 `BEGIN/COMMIT`，嵌套调用会 `BEGIN` 两次报错。
- **修复**：实现真正的嵌套保护——顶层用 `BEGIN/COMMIT/ROLLBACK`，嵌套用 `SAVEPOINT` 模拟，保证外层提交/回滚整体一致。

### B14【低】`hash.split('$')[4]` 取盐取错位置
- **位置**：`auth.controller.js:34/102`、`user.controller.js:59/84`
- **根因**：存储格式为 `scrypt$N$r$p$salt$hash`，盐在索引 **5**，原代码取 `[4]`（取到的是 `p` 参数）。当前因 `verifyPassword` 解析完整 `password_hash` 而未引爆，但 `users.salt` 列值错误。
- **修复**：四处全部改为 `[5]`。

### B12【保留】`auditLog` 中间件未被挂载（死代码）
- **位置**：`server/src/middleware/auth.js`
- **根因**：`auditLog` 已导出但任何路由均未挂载，属“未接线”的扩展点，并非逻辑错误。
- **处理**：**本次不改**。它依赖 `operation_logs` 表与 `logOperation`，作为可演示的“审计日志扩展点”保留；如需启用，建议在 `admin.routes` 的写操作上统一挂载——属于设计决策，不在“修 bug”范围内。

## 四、修改后的关键代码（节选）

### review.controller.js —— 评价隐藏（评分重算）
```js
function recomputeRating(db, flowerId) {
  const stat = db.get(
    "SELECT COALESCE(AVG(rating),5) AS avg FROM reviews WHERE flower_id = ? AND status = 'visible'",
    [flowerId]
  );
  db.run('UPDATE flowers SET rating = ? WHERE id = ?', [Math.round(stat.avg * 10) / 10, flowerId]);
}
exports.setStatus = (req, res) => {
  const db = req.app.locals.db;
  const id = Number(req.params.id);
  const status = req.body.status === 'hidden' ? 'hidden' : 'visible';
  const target = db.get('SELECT flower_id FROM reviews WHERE id = ?', [id]);
  db.run('UPDATE reviews SET status = ? WHERE id = ?', [status, id]);
  if (target) recomputeRating(db, target.flower_id);
  logOperation(db, req.user, '评价', status === 'hidden' ? '隐藏评价' : '显示评价', `评价 #${id}`);
  return ok(res, null, status === 'hidden' ? '评价已隐藏' : '评价已显示');
};
```

### jwt.js —— 安全校验
```js
function verify(token) {
  if (!token || typeof token !== 'string') throw new Error('缺少访问令牌');
  const parts = token.split('.');
  if (parts.length !== 3) throw new Error('访问令牌格式非法');
  const [h, p, s] = parts;
  let header;
  try { header = JSON.parse(base64urlDecode(h).toString('utf8')); }
  catch (err) { throw new Error('访问令牌头部非法'); }
  if (!header || header.alg !== 'HS256' || header.typ !== 'JWT') throw new Error('访问令牌算法不受支持');
  const expected = crypto.createHmac('sha256', config.jwtSecret).update(`${h}.${p}`).digest('base64')
    .replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');
  const a = Buffer.from(expected), b = Buffer.from(s);
  if (a.length !== b.length || !crypto.timingSafeEqual(a, b)) throw new Error('访问令牌签名校验失败');
  const payload = JSON.parse(base64urlDecode(p).toString('utf8'));
  if (payload.exp && payload.exp < Math.floor(Date.now() / 1000)) throw new Error('访问令牌已过期，请重新登录');
  return payload;
}
```
